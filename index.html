Bab 1 — Dua Cara Menggunakan AI untuk Developer

Sebelum membahas harga dan rekomendasi, penting untuk memahami bahwa ada dua pendekatan berbeda dalam menggunakan AI untuk pekerjaan coding. Keduanya berbeda dari sisi cara kerja, harga, dan kegunaannya.

1.1 Pendekatan A — AI Code Editor (Editor yang Sudah Berisi AI)

AI Code Editor adalah program teks/coding yang sudah menyatu dengan kecerdasan buatan di dalamnya. Developer tidak perlu keluar dari aplikasi coding-nya — AI sudah ada di dalam editor yang sama.

Bayangkan seperti ini:

Analogi: Seperti menyetir mobil baru yang sudah ada GPS, kamera mundur, dan sensor parkir terintegrasi langsung di dashboard — semuanya tersedia tanpa harus pasang aksesori tambahan.

Contoh aplikasi jenis ini:

Nama Aplikasi Harga/Bulan Cara Kerja Cocok Untuk
Cursor AI $20 (Rp 354.000) Editor coding lengkap dengan AI Claude/GPT terintegrasi. Bisa membaca banyak file sekaligus. Web & Mobile Dev harian
VS Code + GitHub Copilot $10 – $19 (Rp 177rb – 336rb) Ekstensi yang dipasang di VS Code (editor populer). AI membantu autocomplete dan menjawab pertanyaan. Semua jenis developer
Windsurf (Codeium) $0 – $15 (Rp 0 – 265.500) Editor AI alternatif Cursor, lebih ringan. Punya fitur multi-agent untuk otomatisasi tugas coding. Developer budget ketat
Catatan: VS Code sendiri adalah editor gratis. GitHub Copilot adalah "ekstensi berbayar" yang ditambahkan ke VS Code untuk memberi kemampuan AI. Cursor AI adalah editor baru yang dirancang dari awal untuk AI — lebih canggih tapi harganya lebih mahal.

1.2 Pendekatan B — Berlangganan AI Langsung (Chat + API)

Cara kedua adalah berlangganan langsung ke layanan AI seperti Claude, ChatGPT, atau Gemini. Developer menggunakan AI melalui website chat (seperti WhatsApp tapi untuk tanya-jawab kode), atau melalui API yang bisa dipasang di editor.

Analogi: Seperti membeli nomor GPS premium yang bisa dipasang di mobil mana saja — termasuk mobil lama. Anda membeli layanannya langsung, lalu pasang sendiri di mana Anda butuhkan.

Dua cara mengakses AI langsung:

  • Via Website/Aplikasi Chat: Buka claude.ai, chatgpt.com, atau gemini.google.com — lalu tanya seperti chatting biasa
  • Via API + Editor Extension: Dapat 'kunci akses' (API key) dari OpenAI/Anthropic/Google, lalu pasang di VS Code lewat ekstensi seperti Continue.dev atau Cody

Bab 2 — Memahami Token dan Limit Secara Sederhana

Salah satu hal yang sering membingungkan saat menggunakan AI adalah istilah "token" dan berbagai jenis "limit". Bagian ini menjelaskan semuanya dengan bahasa yang mudah dipahami.

2.1 Apa Itu Token?

Analogi Sederhana: Bayangkan AI seperti orang yang bisa membaca tulisan, tapi ia menghitung bukan per kata, melainkan per "potongan" kecil. 1 token ≈ 1 kata pendek dalam bahasa Inggris, atau sekitar 3-5 karakter. Kalimat "Hello, how are you?" = 5 token. Fungsi JavaScript 50 baris ≈ 400 token.

Sederhananya: Token adalah satuan ukuran untuk mengukur "seberapa banyak" teks yang masuk ke AI dan keluar dari AI.

Jenis Penjelasan Contoh
Input Token Teks/kode yang Anda kirim ke AI untuk dibaca "Tolong perbaiki bug ini: [kode 200 baris]" = ±1.600 token
Output Token Jawaban/kode yang dihasilkan AI untuk Anda Solusi bug 80 baris kode + penjelasan = ±800 token
Context Window Batas total token yang bisa dibaca AI dalam satu sesi Claude: 200.000 token = bisa baca ±150.000 kata sekaligus

2.2 Kenapa Ada Limit?

Analogi Memori Otak: Bayangkan AI punya "kapasitas ingatan sementara" saat bekerja. Semakin banyak kode yang Anda minta ia baca sekaligus, semakin penuh ingatannya. Jika sudah penuh, AI akan "lupa" bagian awal percakapan — atau Anda harus mulai sesi baru.

Ada tiga jenis limit yang berbeda:

Jenis Limit Artinya Dampak jika Habis
Rate Limit Batas berapa kali bisa bertanya dalam waktu tertentu AI menolak sementara; tunggu beberapa menit
Request Limit Batas jumlah pertanyaan per hari/jam Harus upgrade paket atau tunggu reset harian
Context Window Batas panjang percakapan/kode dalam satu sesi AI mulai lupa konteks awal atau perlu sesi baru
Token Harian/Bulanan Total token yang boleh digunakan dalam periode tertentu (paket API) AI berhenti merespons; harus bayar lebih atau tunggu periode baru

2.3 Kenapa Project Besar Butuh Token Lebih Banyak?

Untuk sistem ERP atau aplikasi besar seperti yang ada di perusahaan kita, kodenya bisa ratusan file. Ketika developer meminta AI menganalisa sebuah error, seringkali AI harus "membaca" tidak hanya satu file, tapi beberapa file yang saling berhubungan.

Jenis Pekerjaan Developer Estimasi Token per Sesi Kebutuhan Context Window
Fix bug sederhana (1 file) 2.000 – 5.000 token Kecil (semua AI cukup)
Analisa modul ERP (5-10 file) 20.000 – 50.000 token Sedang (GPT-4 & Claude cukup)
Refactor sistem ERP lama (seluruh modul) 80.000 – 150.000 token Besar — Claude UNGGUL (200K limit)
Dokumentasi seluruh project 100.000 – 200.000 token Sangat Besar — hanya Claude yang sanggup penuh
🎯 Poin Penting untuk Manajemen
Sistem ERP kita yang sudah berjalan bertahun-tahun = banyak kode lama yang saling terhubung. Untuk menganalisa dan memperbaiki kode seperti ini, dibutuhkan AI dengan "memori" besar. Claude adalah satu-satunya AI di harga $20/bulan yang memiliki context window 200.000 token — setara dengan membaca novel setebal 600 halaman sekaligus.

3.2 Profil Singkat Masing-Masing AI

Claude AI — Terbaik untuk Developer

Claude dibuat oleh Anthropic, sebuah perusahaan keamanan AI yang didirikan mantan peneliti OpenAI. Claude dirancang khusus untuk menghasilkan output yang akurat, aman, dan konsisten.

  • Kelebihan: Paling unggul dalam memahami kode kompleks, debugging sulit, dan analisa sistem besar
  • Kelebihan: Context window 200.000 token — bisa membaca seluruh modul ERP sekaligus
  • Kelebihan: Jawaban paling stabil dan konsisten — jarang memberikan kode yang langsung error
  • Kelebihan: Sangat baik dalam membuat dokumentasi teknis yang rapi dan terstruktur
  • Kekurangan: Tidak memiliki fitur generate gambar
  • Kekurangan: Harga sedikit lebih tinggi untuk paket enterprise (Claude Max $100/bulan)

ChatGPT — Populer tapi Kurang Konsisten

ChatGPT dibuat oleh OpenAI dan merupakan AI paling populer di dunia. Sangat cocok untuk penggunaan umum, namun untuk pekerjaan coding yang kompleks, konsistensinya masih di bawah Claude.

  • Kelebihan: Ekosistem terlengkap — plugin, integrasi Microsoft Office, DALL-E untuk gambar
  • Kelebihan: Komunitas paling besar — banyak tutorial dan panduan tersedia
  • Kekurangan: Jawaban untuk coding sering tidak konsisten — satu pertanyaan bisa dapat jawaban berbeda
  • Kekurangan: Sering menghasilkan kode yang error atau tidak sempurna untuk project kompleks
  • Kekurangan: Context window lebih kecil (128K) — kurang ideal untuk project ERP besar

Gemini AI — Terbaik untuk yang Sudah Pakai Google

Gemini dibuat oleh Google dan paling kuat integrasinya dengan ekosistem Google (Gmail, Drive, Docs, Sheets). Untuk coding murni, performanya masih di bawah Claude dan ChatGPT.

  • Kelebihan: Integrasi langsung dengan Google Workspace — ideal jika perusahaan pakai Gmail/Drive
  • Kelebihan: Tier gratis cukup kuat untuk kebutuhan ringan
  • Kekurangan: Performa coding dan debugging masih di bawah Claude dan ChatGPT
  • Kekurangan: Kurang optimal untuk project enterprise atau kode yang kompleks

Bab 8 — Risiko dan Panduan Penggunaan Aman

Penggunaan AI di perusahaan perlu dikelola dengan bijak. Berikut adalah risiko yang perlu diwaspadai beserta langkah-langkah mitigasinya.

8.1 Risiko yang Perlu Diperhatikan

Risiko Penjelasan Cara Mitigasi
🔴 Kebocoran Source Code Kode yang dikirim ke AI tersimpan di server pihak ketiga dan berpotensi digunakan untuk melatih model baru Gunakan paket Claude Pro/Team yang punya opsi 'tidak menyimpan data untuk training'
🔴 Kebocoran Logika Bisnis Algoritma dan proses bisnis unik perusahaan bisa terbaca AI yang diakses banyak pihak Buat SOP: kirim hanya bagian kode yang dibutuhkan, bukan seluruh sistem
🟡 Kode AI yang Mengandung Bug AI bisa menghasilkan kode yang terlihat benar tapi punya celah keamanan (security vulnerability) Wajibkan code review oleh developer senior sebelum kode AI masuk ke production
🟡 Ketergantungan Berlebihan Developer terlalu bergantung pada AI dan tidak mengembangkan kemampuan sendiri Gunakan AI sebagai asisten, bukan pengganti. Wajibkan dev memahami kode yang dihasilkan AI
🟢 Halusinasi AI AI kadang memberikan informasi yang salah dengan percaya diri, terutama untuk teknologi baru Developer wajib verifikasi semua kode AI sebelum dipakai

8.2 Panduan Penggunaan AI yang Aman

Yang BOLEH dilakukan:

  • Kirim bagian kode kecil (satu fungsi/file) yang perlu diperbaiki, bukan seluruh project
  • Gunakan data dummy atau data anonim saat meminta AI menganalisa struktur database
  • Gunakan fitur Privacy Mode atau aktifkan opsi 'tidak gunakan data untuk training'
  • Minta AI menjelaskan logika kode — bukan hanya menyalin output-nya begitu saja
  • Lakukan code review sebelum kode AI masuk ke repository/production

Yang TIDAK BOLEH dilakukan:

  • Upload password, API key, atau kredensial database ke AI
  • Kirim data pelanggan/transaksi nyata ke AI untuk dianalisa
  • Langsung pakai kode dari AI tanpa diperiksa terlebih dahulu
  • Mengandalkan AI untuk keputusan keamanan sistem tanpa review dari tim
🏢 Rekomendasi Kebijakan Perusahaan
1. Buat dokumen SOP penggunaan AI untuk tim developer yang mencakup: data apa yang boleh/tidak dikirim ke AI, dan prosedur review kode sebelum deploy ke production.

2. Aktifkan opsi 'Zero Data Retention' atau setara pada paket AI yang dipilih.

3. Tunjuk satu senior developer sebagai 'AI Champion' yang bertugas memastikan penggunaan AI sesuai kebijakan.

4. Evaluasi penggunaan dan manfaat AI setiap 3 bulan.
